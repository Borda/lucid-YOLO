# `scripts/`

Development tooling. Nothing here ships — the four commands that do (`lucid-yolo`, `lucid-data`, `lucid-eval`, `lucid-predict`) live under `src/lucid_yolo/cli/` and cover a full tier run from an installed wheel alone (AGENTS.md sec. 2). This directory is what a developer working *in* the repository runs instead: golden regression, release gating, figure/report generation, and every repo-content check `make gate` enforces on commit.

Three subtrees, by what a script is for:

| Subtree | What lives there | Runs via |
| -- | -- | -- |
| `scripts/` (this level) | Core tooling: goldens, release gate, training-run outputs, dataset generalization | `make` targets, or direct CLI |
| `scripts/lint/` | Repo-content checkers | `.pre-commit-config.yaml` local hooks, individually callable |
| `scripts/_tests/` | Functional-core tests for every script above | `pytest` (part of `make test` / `make gate`) |

Every script below is a `main(argv) -> int` CLI with Google-style docstrings and doctested public functions (`make test` runs `--doctest-modules` over this whole directory, not just `src/`). None of them import from `github.com/ultralytics/*` — AGENTS.md's prime directive applies here exactly as it does to `src/`.

## Core (`scripts/*.py`)

| Script | Does | Invoked by | Test |
| -- | -- | -- | -- |
| `bench_input_path.py` | Times device transfer, the restore hook and public box/rotated/keypoint padding, plus 300-mask decode; emits one JSON record with median milliseconds and CUDA peak allocated MiB (`null` elsewhere). Host collation is untimed. Uses entry points shared with the parent revision for the combined A100 comparison. | `python scripts/bench_input_path.py --device auto`; `--help` lists iteration and workload controls | `_tests/test_bench_input_path.py` |
| `check_goldens.py` | Golden harness (WP-005): recomputes every `goldens/*.json` producer and compares against the frozen value, tolerance-checked. A live golden must pin every metric its producer emits — one that gained a metric fails rather than passing on the subset it already carried; a frozen file is exempt, since a past release pinned what existed then. A frozen file byte-identical to a live sibling reuses that sibling's producer output and reports `SAME as live`, which is 41 of the 50 entries and takes the sweep from 34.6 s to 7.1 s; every file still parses, validates and compares against its own stored values. Also the `golden-check` pre-commit hook. | `make golden` (so also `make gate`), `make golden-gpu --include-gpu`, the `Frozen golden regression` step in `ci-tests.yml`, or standalone via `pre-commit run --hook-stage manual golden-check` | `_tests/test_check_goldens.py` |
| `golden_producers.py` | The zero-argument, deterministic producer functions `check_goldens.py` discovers and recomputes — one per frozen golden. | Imported by `check_goldens.py`; also imported directly as a fixture source by several `tests/` suites (`tests/assign/`, `tests/data/`) | doctests only (no dedicated `_tests/test_golden_producers.py` — its producers are exercised transitively via `check_goldens.py` and the goldens it feeds) |
| `freeze_goldens.py` | Freezes the live goldens into `goldens/frozen/<minor>/`, skipping the `"freezable": false` ones whose producers are pinned to an external generator (WP-154c). The flag is no longer taken on trust: every producer runs in a fresh interpreter first and the freeze refuses on a contradiction in either direction — a generator-derived golden declaring itself freezable, or a pure one carrying a stale `false`. Nothing is copied on refusal, and the derivation costs nine producer runs, paid by a release and never by `make gate`. Also the **only writer** of `goldens/frozen/MANIFEST.sha256`: a release freeze seals the files it copied, and `--reseal` recomputes every digest — the one sanctioned way to record a principal-approved frozen-golden move (WP-168). | `make freeze-goldens MINOR=0.N`; `--reseal` by hand, after an override | `_tests/test_audit_frozen_manifest.py` (with the checker it feeds) |
| `release_guard.py` | Release gate (WP-006): a candidate tag ships only if it's a shippable `v0.MINOR.PATCH` string (ADR-002: no 1.0, ever), its changelog section exists, `lucid_yolo.__version__` is the version the tag names, `goldens/frozen/<MAJOR.MINOR>/` is non-empty, every shipped import is declared at runtime, and `make gate` is green. The version and frozen-golden checks are WP-168's: nothing had ever compared a tag against either. No-op (exit 0) when `HEAD` isn't exactly a tag. | Release WPs [PRINCIPAL]; also the `release-guard` pre-commit hook, every commit / `pre-commit run --all-files`, or standalone via `pre-commit run --hook-stage manual release-guard` | `_tests/test_release_guard.py` |
| `overfit_micro.py` | Overfit-100 integration golden (WP-040): trains the full stack on a fixed ~100-image synthetic slice and gates on train recall@0.5 ≥ 0.95. Needs an accelerator; `--epochs`/`--batches` cap the run as a probe that reports its score without the floor (the development-gates notebook's fast mode). | `make overfit`, `make overfit FREEZE=1` | `_tests/test_overfit_micro.py` (`gpu`/`data`-marked, run via `make test-gpu`) |
| `shapes_regression.py` | Synthetic-shapes generalization golden (WP-083): trains on 1,800 generated scenes, scores a held-out 200 through both decode paths. Needs an accelerator, ~2 min. | `make shapes`, `make shapes FREEZE=1` | `_tests/test_shapes_regression.py` (`gpu`/`data`-marked, run via `make test-gpu`) |
| `plot_training.py` | CLI over `lucid_yolo._viz.curves` (WP-189): the panels, series tables and CSV reader live in the package, where the notebooks share them; this script adds the deterministic SVG save the reproduction report needs — fixed hashsalt, suppressed date metadata — and the `Agg` backend selection. | Release WPs, by hand | `tests/viz/test_curves.py` for the figure; doctests for the save and the CLI |
| `draw_predictions.py` | CLI over `lucid_yolo._viz.overlay` (WP-189): the four per-task drawers, the renderer table and the checkpoint-to-axes path live in the package, where the notebooks share them; this script owns the argument parse, the file write and the `Agg` backend selection. The release's worked example (WP-067): boxes, instance masks, rotated quadrilaterals or point sets depending on task. | Release WPs, by hand | `_tests/test_draw_predictions.py` (the command); `tests/viz/test_overlay.py` (the drawing) |
| `dump_debug_grid.py` | Debug visualizer (WP-015): dumps an annotated grid of `--samples` images run through the Phase-1 augmentation pipeline, for eyeballing mosaic/affine/mixup/copy-paste behaviour. | By hand, ad hoc | doctests only (no dedicated `_tests/test_dump_debug_grid.py`) |
| `absolutize_readme.py` | Rewrites the README's repo-relative links to absolute ones at packaging time, so PyPI's rendering doesn't 404 (WP-113b). Opt-in (`--ref` / `LUCID_YOLO_RELEASE_REF`), reverted after a local build. | `release.yml`, ahead of `uv build` | `_tests/test_absolutize_readme.py` |

## Lint (`scripts/lint/*.py`)

Every checker here used to be a `tests/meta/` pytest test scanning the live repo tree — a lint check wearing a unit test's clothes (WP-129/130). Each is now a standalone CLI plus a `.pre-commit-config.yaml` local hook, individually callable without running the rest of the suite: `pre-commit run <hook-id>`.

| Script | Hook id | Checks | Runs when |
| -- | -- | -- | -- |
| `audit_licenses.py` | `license-audit` | Every installed distribution's declared license is Apache-compatible; flags an undeclared license per tier; scans shipped native binaries for copyleft libraries a wheel vendors without declaring. | Every commit (`always_run` — installed-environment state can drift without a tracked-file diff) |
| `check_commit_trailers.py` | `commit-trailers` | The commit message matches AGENTS.md sec. 5: Conventional Commits subject, mandatory `WP:`/`Provenance:`/`Assumptions:`/`Gate:` trailers, provenance ids resolvable against `docs/PROVENANCE.md`. | `commit-msg` stage, on the message being written |
| `check_commit_trailers.py` | `commit-trailers-history` | Same contract, re-validated (`--unpushed`) over every local commit not yet pushed: `@{upstream}..HEAD`, or `HEAD --not --remotes` on a branch with no resolvable upstream (never pushed, or a fork pull request checked out by URL) — the `--all-files`-reachable sibling of `commit-trailers`, which has no commit message to read outside `commit-msg` stage. A commit authored under GitHub's App address (`…[bot]@users.noreply.github.com`) is skipped by name rather than validated; the DCO GitHub App applies the same exemption to the sign-off. | Every commit / `pre-commit run --all-files`, or standalone; skipped in the CI `precommit` job — branch commits never land under squash merge; `pr-message.yml` checks the title and description that do |
| `audit_test_doctests.py` | `test-doctest-audit` | Every non-fixture, non-`test_` module-level helper under `tests/` and `scripts/_tests/` carries a `>>>` doctest Example. | A `test_*.py` file changes, under either root |
| `audit_doctest_fences.py` | `doctest-fences` | Every docstring doctest under `src/` sits in a ```` ```pycon ```` block closed after exactly one blank line; a `>>>` in a plain string or comment is not read. `scripts/` and `tests/` are not checked. | A `.py` file under `src/` changes |
| `audit_flat_test_groups.py` | `flat-test-group-audit` | A mechanical group of 3+ `test_` functions — a shared name prefix that also names something the file calls, not merely a shared topic noun — sits under a `class Test<Subject>:` rather than flat at module level. | A `test_*.py` file changes, under either root |
| `audit_docs_present.py` | `docs-present` | The docs-governance register is structurally intact: required files exist, `ASSUMPTIONS.md`/`ROADMAP.md`/`DECISIONS.md`/`PROVENANCE.md` parse as contiguous registers, cross-links resolve. | A `docs/*.md`, `AGENTS.md`, or `README.md` changes |

`_common.py` here holds what the checkers share: `REPO_ROOT`, the `--repo-root` option, a sorted `rglob` walk and the `<name> FAILED: N ...` report printer. Each checker puts the repository root on `sys.path` and imports `scripts.lint._common` (a plain `from _common import` would run under pre-commit but mypy cannot resolve it). `scripts/_common.py` is the top-level counterpart: `REPO_ROOT` and the SHA-256 `digest` the golden scripts share.

Three stock hooks need no script: `no-ipynb-tracked` is a `language: fail` hook on `\.ipynb$` (a notebook is a jupytext `notebooks/*.py` source and the `.ipynb` is what `make notebooks` writes into gitignored `docs/notebooks/`, WP-188 — a `git add -f` matches the staged path at the commit that makes it), and the `pygrep` hooks `test-name-filler-adverbs` (no `still`/`just`/`actually`/`properly`/`correctly` in a test function name under `tests/` or `scripts/_tests/`) and `tqdm-auto-only` (no plain `tqdm` import under `tests/`, `scripts/` or `notebooks/`, where ruff's per-file ignores skip its `TID251` ban).

Three more hooks live in `.pre-commit-config.yaml` under `repo: local` but audit core scripts rather than `scripts/lint/`, listed in the core table above: `golden-check` → `check_goldens.py`, `release-guard` → `release_guard.py`, `commit-trailers-history` → `check_commit_trailers.py --range`. `release-guard` and `commit-trailers-history` carry `stages: [pre-commit, manual]` — every commit and `pre-commit run --all-files`, plus standalone via `pre-commit run --hook-stage manual <id>`. `golden-check` carries `stages: [manual]` alone since WP-162: at 34.6 s it is not a quick check, and `make gate` already recomputes the same goldens through `make golden`.

## Tests (`scripts/_tests/*.py`)

Every test here is the **functional core** of the script it's named for — `test_<script>.py`, script functions exercised against synthetic `tmp_path` fixtures (or, for the `scripts/lint/` checkers, loaded with `script_loader.load_script` and called directly). What runs against the *live* repo tree is the corresponding pre-commit hook or `make` target above, not pytest — pytest owns the functional core, the hook or target owns enforcement. No test here asserts that the live tree is clean: `lint.yml` and `make gate` run every hook with `--all-files`, so such a test only repeated the hook.

`conftest.py` here is shared session setup for the drawing suite (`test_draw_predictions.py`): forces the `Agg` matplotlib backend before `pyplot` is imported anywhere in the session, closes every figure a test opens so unclosed figures don't leak across tests, and puts `tests/predict/` on `sys.path` for the planted checkpoint, and this directory too, so a suite can `from script_loader import load_script` — the one `importlib` recipe every `test_audit_*.py` shares. `tests/viz/conftest.py` does the same for the package-side drawing suites.

This directory sits under `scripts/`, not `tests/`, because its subject does: a test of a `scripts/` module belongs beside the module it tests, the same way `tests/unit/` mirrors `src/`. `make test` and `make gate` already scan it — both pass `scripts` as a collection root alongside `src` and `tests`.
